## Lessons

1. **Supporting files drift too.** The Core memory rule "spec edits keep §97/§98/§99 in lockstep" only protects banner+changelog+health files. Auxiliary supporting files like `health-dashboard.md` are not lockstep-tracked and accumulate drift between regenerator runs. Pattern matches Phase 136/139 stale-prose finding but in a different surface — worth keeping on the periodic-sweep list.
2. **Single source of truth wins again.** `dashboard-data.json` is regenerated by `generate-dashboard-data.cjs`; the markdown summary should ideally be regenerated alongside it. Future enhancement candidate: have `generate-dashboard-data.cjs` also patch the dashboard.md banner+breakdown table (similar to spec-index auto-regen). Out of scope for Phase 28.
3. **Allowlist-count drift is silent.** No CI gate compares the markdown's allowlist table to `EXTERNAL_REPO_PREFIXES`. Low priority since it's documentation-only, but flag for future hardening if a third drift instance appears.
