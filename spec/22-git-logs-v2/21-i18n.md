# Internationalization (i18n) (v2)

**Version:** 2.3.0  
**Updated:** 2026-04-25

Rules for translatable strings in the WordPress plugin.

---

## Text domain

- **Slug:** `git-logs`
- **Declared in:** `git-logs.php` plugin header → `Text Domain: git-logs`
- **Loader:** `load_plugin_textdomain('git-logs', false, dirname(plugin_basename(__FILE__)) . '/languages')` called on the `init` hook (priority 0).
- **Languages folder:** `languages/` at plugin root. POT generated by `wp i18n make-pot . languages/git-logs.pot`.

---

## What IS translatable

Wrap with `__()`, `_e()`, `_n()`, `_x()`, `esc_html__()`, etc., always passing `'git-logs'` as the second arg.

| Surface | Examples |
|---------|----------|
| Admin menu labels | "Profile", "Roles", "AccessToRoles", "GitProfile", "Repo", "RepoVersion", "History", "Action" |
| Page titles + section headings | "Add GitProfile", "First-run Bootstrap" |
| Form labels + help text | "Profile URL", "Trailing slash optional; canonicalized on save" |
| Button labels | "Regenerate", "Save", "Delete" |
| Notices / admin warnings | "Plugin DB unavailable: %s" |
| Bootstrap UX copy | "Copy and store securely — this is the only time we will show this token." |
| Error messages shown to admin user | "Profile creation failed. See diagnostics." |
| Site Health test labels + descriptions | §20 entries |

Use `sprintf` + `__()` together for placeholders, never string concatenation.

```php
echo esc_html(
    sprintf(
        // translators: 1: profile name, 2: role name
        __('Profile %1$s assigned to role %2$s.', 'git-logs'),
        $profileName,
        $roleName
    )
);
```

## What is NOT translatable (stays English)

These are stable identifiers across systems and translating them would break integrations.

| Surface | Why it stays English |
|---------|----------------------|
| `GL-*` error codes | Stable API contract; clients grep by code. |
| Enum names (e.g. `AcceptAllRepos`, `Active`, `Append`) | Stored in DB, sent in API, used as identifiers. |
| Permission names (e.g. `HistoryView`, `AppCreate`) | Identifiers; checked in code. |
| Role names (e.g. `Admin`, `Editor`) | Stable across installs. **Display label** may be translated separately if needed. |
| REST route segments (`/append-log`, `/get-logs`) | URL contract. |
| `LogSeverity` names | Mapped to numeric comparison; stable. |
| Hook names, capability names, transient keys | Code-level identifiers. |
| Audit `Detail` payload keys | Machine-readable; consumers parse them. |
| `ConfigKv` key names | Stable config surface. |

If a UI surface needs a translatable label for one of the above, store it in a separate `*Label` translation table or map it in PHP at render time:

```php
$roleLabels = [
    'Admin'  => __('Administrator', 'git-logs'),
    'Editor' => __('Editor',        'git-logs'),
];
echo esc_html($roleLabels[$role->Name] ?? $role->Name);
```

## RTL + locale formatting

- Admin CSS includes RTL companion `assets/css/admin-rtl.css` generated via `wp i18n` tooling.
- Dates use `wp_date()` with the user's locale, not hard-coded `date()`. Format strings come from `get_option('date_format')` + `get_option('time_format')`.
- Numbers use `number_format_i18n()` for any count > 999.

---

## Translator-friendly source rules

- Every translatable string with a placeholder must have a `// translators:` comment immediately above the call.
- Avoid splitting sentences across multiple `__()` calls; translators need full context.
- Avoid HTML inside translation strings; if unavoidable, use `<span>` with classes — never inline styles.
- Pluralization always via `_n()` or `_nx()`, never PHP ternaries on a count.

---

## CI check

A linter runs in CI:

```bash
wp i18n make-pot . /tmp/git-logs.pot --skip-audit
diff -u languages/git-logs.pot /tmp/git-logs.pot
```

Failure means a string was added or removed without regenerating POT. Build fails until `languages/git-logs.pot` is updated.
